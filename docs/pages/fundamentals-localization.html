Fundamentals

Localization

Formats come from Intl; texts come from Kern in English or German, and every one can be replaced.

Locale

Components that format dates, times, numbers or sizes take a locale (BCP 47). Without it they use <html lang>, then the browser language.

Texts

Buttons, hints, validation messages and names for screen readers are Kern texts. Kern ships them in English and German and picks the language in this order:

  1. the language set with setKernLocale(),
  2. <html lang>, also when it changes later,
  3. English.

The browser language is not used for texts, so they match the language of the app. A change re-renders all components at once, including validation messages already shown.

import { setKernLocale } from '@yfridelance/kern'; setKernLocale('de'); // German texts setKernLocale(); // follow <html lang> again

Up to version 0.8 the texts were German by default. An app that relies on this sets <html lang="de"> or calls setKernLocale('de').

More languages and own wording

setKernStrings() adds texts for a language or replaces single ones; missing texts fall back to the built-in ones of the base language, then English. Texts for a region (de-CH) win over those for the language (de).

import { setKernLocale, setKernStrings } from '@yfridelance/kern'; setKernStrings('fr', { 'kern-pagination.labelNext': 'Page suivante', 'kern-pagination.labelRange': '{from}–{to} sur {total}', }); setKernStrings('de-CH', { 'kern-table.labelEmpty': 'Nüt da' }); setKernLocale('fr');

Apps with their own i18n call setKernLocale() where they switch the language:

translate.onLangChange.subscribe(({ lang }) => setKernLocale(lang));

Language switcher

kern-language-select lets people pick the language: as a dropdown with names or codes, with or without flags, or side by side. It reports the choice with kernChange; the app switches its own texts and Kern's.

switcher.addEventListener('kernChange', (e) => setKernLocale(e.detail.value));

Single components

Every text is also a property, mostly starting with label, e.g. close-label on kern-dialog, label-invalid on typed fields, label-range on kern-pagination. A property set on a component wins over the Kern text. Placeholders like {n} or {name} are replaced. The property tables on each component page list them with their English and German default.

<kern-pagination total="380" label-range="{from}–{to} of {total} devices"></kern-pagination>

Functions take their texts as options (confirmLabel, cancelLabel for confirm(), closeLabel for toast()) and otherwise use the Kern texts too. setToastRegionLabel() fixes the name of the region all toasts share; without it the name follows the language.
